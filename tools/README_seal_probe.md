# 印章提取独立验证

在项目目录使用现有虚拟环境运行。工具仅使用本机文件和已有依赖。每次创建独立输出子目录，包含候选 PNG 和 `diagnostics.json`，不会覆盖以往结果。

```powershell
Set-Location D:\code\Effi
.\.venv\Scripts\python.exe .\tools\seal_probe.py 'D:\资料\印章填报表.pdf' --output-dir 'D:\验证输出'
.\.venv\Scripts\python.exe .\tools\seal_probe.py 'D:\资料\印章填报表.docx' --output-dir 'D:\验证输出'
.\.venv\Scripts\python.exe .\tools\seal_probe.py 'D:\资料\印章采集页.png' --output-dir 'D:\验证输出' --local-ocr
```

扫描 PDF 可添加 `--local-ocr`。此选项先检查项目已有两套本地模型的必要文件，再调用现有 `ocr_runtime.create_ocr` 和 `ocr_utils.extract_ocr_items`。默认不初始化 OCR，不下载模型。当前仅接受置信度至少 0.8 的标签。

PDF 自动遍历全部页，默认以 300 DPI 渲染，也支持 `--dpi 200`。渲染路径覆盖页面上的内嵌图、矢量和扫描内容，保留页面显示效果。程序只接受采集标签位于闭合矩形边框顶部内侧或紧邻上方的区域。矩形检测和标签距离使用保守启发式规则，仍可能漏检或误定位。只有页面标题而没有明确区域关系时可能失败。倾斜、断框、无框、标签拆行、低置信度 OCR 都可能需要人工介入。

DOCX 直接读取明确采集标签所在表格行中的内嵌图片，输出基于原始图片像素，不进行整页排版渲染。不能可靠处理浮动图、跨行标签、文本框、Word 绘图及部分矢量编码。原图可能包含在 Word 中被隐藏的裁剪部分，需对照原件检查。必要时由人工将 DOCX 导出 PDF 后重新验证。DOCX 不报告页码，因为内嵌图片没有可靠分页信息。

自动定位失败时，可明确提供人工已确认的采集区域。PDF 必须同时提供页码。坐标为渲染后图片的整数像素，依次为左上角 X、Y、宽、高。图片使用 EXIF 方向矫正后的像素坐标。

```powershell
.\.venv\Scripts\python.exe .\tools\seal_probe.py 'D:\资料\申请资料.pdf' --output-dir 'D:\验证输出' --page 2 --dpi 300 --region 400 1100 1200 900
```

上述坐标仅演示参数格式，应替换为实际采集区。人工区域应排除标题和边框，并给印章留出足够白边。

裁剪仅以亮度/颜色通道阈值确定内容边界，输出始终来自原始 RGB 像素，附带原图中的约 3% 安全留白。透明源图在白底合成。不会增强、锐化、改色、拉伸或修复。阈值可能遗漏极淡笔画，脏点也可能扩大裁剪范围。内容过于靠近区域边缘时返回失败，避免输出明显截断的候选。一个区域内的多个印章或签名会保留为一个候选，不擅自拆分或选择。

诊断记录文件类型、PDF 页码、方法、区域数量、候选数量、裁剪像素尺寸、总耗时及失败原因。日志使用固定文字，不输出 OCR 内容、原文件名或客户字段。PNG 本身包含印章业务信息，应保存在合适的本地目录。

人工验收时逐个对照原文件的页码与采集区，检查外圈、细笔画是否完整，颜色与比例是否一致，是否混入标题、边框、无关文字或其他印章。`region_found` 仅代表找到关联区域，`candidate_saved` 仅代表输出了候选，`human_confirmed` 始终为 false。候选即使只有一个，也必须人工确认。多个候选全部输出，不自动选中。返回码 0 表示有候选待复核，2 表示失败或处理未完成。出现 `incomplete` 时应先排查诊断错误。

本工具与正式 GUI、Word 填充和打包配置独立，没有新增依赖。当前打包配置不包含此工具，因此本阶段不会增加发行 EXE 的体积。后续接入需重新评估。
