# 电子印章采集手动验证

在 PyCharm 中使用项目现有 `.venv` 解释器，运行 `application_extractor.py`。

1. 选择个人 Word 模板，在固定客户信息区下方找到“电子印章采集”。
2. 点击“选择其他文件”，选择 DOCX，再点击“提取印章”。DOCX 内嵌原图和 PDF 匹配页共用待框选候选卡片。原图不能勾选，通过卡片旁的“框选”保存实际裁剪后才可勾选。
3. 点击“预览”检查内容、颜色和完整性，勾选最多三张。所有候选都能用“上移 / 下移”交换相邻位置，勾选状态随图片移动。Word 生成直接按当前列表中已勾选图片的顺序填入，无需确认按钮。
4. 分别检查零张、一张、两张、三张，确认依次填入从左到右的采集框。检查圆章、方章、宽签名、竖向图及透明图片的比例、边框和分页。插入使用保存后的实际裁剪图片字节，不再次重编码。
5. 修改勾选或顺序后直接生成，Word 应立即使用当前勾选结果。没有选择时采集框留空。重选文件、切换来源、重新导入申请表后清除上一份候选及勾选状态；切换 Word 模板保留候选。
6. 选择损坏 DOCX、特殊绘图、链接图或不支持的图片编码，检查明确提示，并确认仍可生成不含印章的原有申请表。
7. 点击任一卡片旁的“框选”打开对应完整原图。拖动框选后查看实际裁剪预览，“保存裁剪”替换当前候选并自动勾选，“另存为新印章”新增并自动勾选。再次框选仍打开同一完整原图。可切换“原始像素 1:1”，通过滚动条精确检查。两种保存后都可直接生成 Word。已选满三张时，若保存需要新增选择，请先取消窗口并取消一张选择。
8. 切换机构模板生成，使用同一勾选列表，依次填入“单位公章采集处（三个样本）”。确认下方委托申明“单位公章”位置留空。

个人与机构模板分别通过“个人章采集处（三个样本）”“单位公章采集处（三个样本）”标题及两行三列嵌套表格结构定位，共用图片居中和尺寸控制，现有模板文件无需调整。每张图片按目标单元格宽度和样本行高等比例缩放，四周预留 12 磅安全距离。正式 Word 渲染、打印和分页效果需在本机 Word/WPS 中验证。

DOCX 主文档的 DrawingML 内嵌位图和 VML 内嵌位图可提取。特殊形状、链接图、不受支持的图片格式会提示未提取对象数量。页眉页脚和嵌入的附件不属于本轮提取范围。Word 中对图片施加的裁剪、旋转及艺术效果不会应用到原图，框选使用原始内嵌图，输出使用保存的实际裁剪图，需人工确认是否合适。

候选及勾选图片只保存在内存中，生成文件包含当前勾选的实际裁剪图片。本模块不依赖 `tools/seal_probe.py`，未增加第三方依赖。

DOCX 仅提取内嵌原图并保留采集表格提示，统一由用户框选，不再在正式候选流程中自动裁剪。同一张原图中的多个印章使用“另存为新印章”，新候选紧邻来源插入。

框选和放大预览为 Effi 主窗口的模态子窗口。检查首次打开、再次打开、任务切换后的显示层级，以及取消、保存、右上角关闭和 Esc 后主窗口是否恢复操作。关闭或取消框选不提交候选修改。

## PDF 页面查找与框选

默认使用上方申请表 PDF；点击“当前 PDF”切回该文件，点击“选择其他文件”直接选择独立 PDF、DOCX 或图片。来源和文件名会持续显示，取消对话框保持原来源及候选。客户信息结果先交付界面，之后自动执行轻量查找，只读原生文字层与已有 OCR 缓存，不新增整页 OCR。未完成整页识别的页码标记为 pending，仍可手动选页框选。需要完整查找时点击现有“提取印章”，才对待识别页面执行原有 120 DPI 本地 OCR 回退；完整结果会缓存，部分结果不会误当成完整负向结果。

PDF 匹配页通过已有 SealCandidate 进入同一候选列表，显示真实低清缩略图和待框选状态。点击后后台以 300 DPI 渲染供框选。首次保存原位替换页面缩略图，保留完整高清来源和页码，再次框选仍打开原页。没有单独的 PDF 页面卡片循环。

未匹配时显示“未自动找到电子印章填报表”，仍可在列表顶部输入 1 至总页数之间的页码，点击“查看 / 框选”。自动识别失败和人工指定页码有明确区别。部分页面 OCR 或渲染失败会给出数量提示，其他已匹配页面仍然可用。

PDF 与 DOCX 的“保存裁剪”都替换当前候选并自动勾选，只有“另存为新印章”才在来源候选旁新增。两种操作均立即更新导出数据，最多勾选三张。原页面不会作为第二张重复来源卡片继续显示。

人工重点验证包含多个填报页的文字 PDF、纯扫描 PDF、没有目标标题的 PDF、旋转页面、损坏或加密文件、无效页码，以及查找过程中切换来源。实际本地 OCR 命中率、窗口交互和 Word 打印效果需在本机检查。模型不可用时提示手动选择页码，不会下载模型。外部 PDF 发生变化后需要重新提取。

## 缩放和工作区

框选窗口支持 Ctrl＋滚轮以鼠标位置为中心缩放，上限 500%，下限兼顾 2% 和整页适配需求，便于缩小宽幅签名。连续滚轮合并到约 16 毫秒一次更新。首次适配等待画布可见且实际宽高有效。普通滚轮上下滚动，空格＋左键双向平移。缩放保留原始像素选区，红框按新比例重绘，保存始终从原图裁剪。适应窗口同时考虑可视宽度和高度。仅渲染当前视口，避免高倍缩放生成整页巨型预览。

主窗口顶部文件操作和模板选择固定。客户信息始终完整显示：左侧为单位及法定代表人，右侧为经办人，两卡片等高；模板切换只影响导出，不隐藏字段或清空数据。客户区无收起按钮、分隔条和滚动条。印章区占据剩余高度，按钮和提示位于列表上方，只有候选列表独立滚动。底部状态栏固定在窗口底部。最小窗口按实际字体和 DPI 的控件请求尺寸计算，避免字段和操作栏被裁切。

手动检查不同窗口高度和 Windows DPI 下的字段完整显示、模板切换数据保留与候选滚轮隔离。框选后反复缩放、平移，再保存并对照原图检查选区及细笔画是否完整。靠近图像边界缩放时，滚动边界会限制鼠标中心保持效果。

点击“开始提取”先完成原有客户信息流程并交付 UI，随后进行零新增 OCR 的印章轻量查找。主流程与按需 PDF 查找继续共用模型和可重入锁，同一实例不并发推理。如果用户已主动启动完整印章 OCR，客户任务可能等待同一把锁，日志会记录。模型按需复用，不增加实例。

框选弹窗默认约 1000×650，按主窗口所在显示器的工作区和 DPI 限制并居中。手动核对主窗口靠近屏幕边缘、多显示器、任务栏和不同缩放比例下的位置，及取消、保存、关闭后的焦点恢复。

性能日志按页记录整页 OCR 调用、命中和耗时，另列标题区 OCR、印章查找子阶段、缩略图/UI、模型锁等待及最终墙钟。标题 OCR 是页面定位子阶段，不能将父子耗时重复相加。最终墙钟包含队列及人工选页等待。未以客户文件测量实际加速比例；本机请分别比较冷启动、重复提取与连续不同文件。

性能对比时分别查看客户信息最终墙钟、[印章自动轻量查找] 与 [印章按需查找]。自动阶段应显示 ocr_calls=0，并列出 deferred 页数。按需阶段逐页输出 OCR 耗时，header_hit/full_hit/full_miss 表示缓存复用，完整缓存再次查找显示本次 ocr_calls=0。输入 PDF 变化或切换来源会校验文件版本及界面任务代次，旧结果不会交付给新客户。

机构字段保留原 run 的字体和下划线。单位信息、经办人姓名和联系方式行使用固定制表位分隔右侧标签，左侧长值改为换行。请用常规和超长单位名称、地址、邮箱手动核对换行及分页。

独立 PNG/JPG/JPEG 来源点击“提取印章”后，直接读取原图字节并生成一个默认勾选的候选，可直接导出，也可框选后原位替换。图片不会执行 PDF 定位或标题 OCR，不做图像增强。切换实际来源或重新导入客户文件会清空旧候选；取消文件选择不清空。
