# 关键决策

以下记录依据 2026-11-11 当前代码和已确认维护要求。

| 决策 | 原因与实现 |
| --- | --- |
| 本地 OCR 与本地处理 | 客户资料留在本机。`ocr_runtime.py` 使用 CPU 和两套固定本地模型，跳过源探测，依赖与模型由开发维护环节准备 |
| 正式交付采用 onedir | `Effi-onedir.spec` 将依赖放入 `_internal`，通过 `COLLECT` 形成完整目录，避免每次启动整体解包 |
| 保留正式与调试入口 | 正式 onedir 为无控制台 EXE，使用运行时钩子关闭身份证实验开关；调试 spec 保留控制台辅助诊断 |
| 共用印章数据结构 | `SealCandidate` 保存当前字节、尺寸、来源、原始引用和 PDF 页码；来源只负责读取，候选、框选及 Word 插图共用 |
| 人工决定裁剪范围 | 自动定位标题不能证明印章正确完整，PDF/DOCX 原图先框选；独立图片可默认勾选，由客服核对 |
| 保存直接生效 | 保存替换当前候选并勾选，另存才在相邻位置新增；生成时直接使用当前勾选，无额外确认状态 |
| 上下移动交换候选 | 候选数据、来源和勾选一同移动，Word 按列表中已选项连续填入三个格，避免视觉与导出排序不一致 |
| 字段始终完整展示 | 左侧单位与法定代表人，右侧经办人；客户区固定，模板只决定导出映射，候选区独立滚动 |
| 客户结果与印章重 OCR 解耦 | 客户识别完成先交付 UI，自动印章查找不新增 OCR；完整扫描通过既有按钮触发，手动选页保留 |
| 缓存优先且区分完整性 | 按路径、文件大小、修改时间验证 PDF 缓存，保存标题区及整页结果；pending 页不能被当成完整负向结果 |
| 同一模型串行推理 | 可重入锁保护主识别与按需查找，复用模型；显式任务可能排队，保留锁等待及墙钟统计 |
| 裁剪保持像素与比例 | 从原始图片或 300 DPI PDF 渲染图裁剪，缩略图只供预览；不增强、锐化或去底，Word 共用安全边距与等比例缩放 |
| 模板结构先校验再填充 | 在现有 run、段落和采集表格中替换，按采集标题定位三格，避免误填委托申明公章段落 |
| 发布前检查完整历史 | 当前工作区干净不代表历史安全。发现未获准公开的 PDF 后暂停推送，历史变更须另行明确授权 |

更改上述决策时，应记录触发原因、影响范围、替代方案和验证结果，避免把单次临时处理写成永久约束。
